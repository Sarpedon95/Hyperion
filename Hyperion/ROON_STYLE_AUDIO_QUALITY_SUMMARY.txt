SIGNAL PATH STEPS EXPLAINED:
───────────────────────────

Step 1: SOURCE
  Data: Track URL file extension
  Example: FLAC
  Status: 🟢 Lossless (if FLAC/WAV/ALAC), 🟡 Lossy (if MP3/AAC)

Step 2: STREAMING
  Data: Server name
  Example: Lyrion Music Server
  Status: 🟢 Lossless (always — server doesn't transcode)

Step 3: DECODE
  Data: Decoding type
  Example: "Lossless decode" for FLAC
  Status: 🟢 Lossless (for lossless formats), 🟡 Lossy (for MP3/AAC)

Step 4: BIT DEPTH
  Data: Inferred from source format
  Example: 24-bit (for FLAC), 16-bit (for ALAC/WAV)
  Status: 🟢 Lossless (always — bit depth is fixed per format)
  Note: AVAudioSession doesn't expose actual bit depth, so inferred from format

Step 5: SAMPLE RATE
  Data: Live from AVAudioSession.sampleRate
  Example: 48.0 kHz
  Status: 🟢 Enhanced (no resampling), 🟡 Converted (resampling needed)
  Logic: Lossless format at common rate (44.1/48) = no resampling

Step 6: VOLUME
  Data: Current volume slider level
  Example: "Full scale" (100%), "75%"
  Status: 🟢 Enhanced (90%+), 🟢 Lossless (50-90%), 🟡 Converted (<50%)

Step 7: OUTPUT
  Data: Current audio route from AVAudioSession
  Example: "Headphones (Stereo)"
  Status: 🟢 Lossless (wired), 🔴 Limited (Bluetooth/AirPlay)

Step 8: VERIFICATION (if bit-perfect)
  Data: Calculated from all above
  Example: "Bit-perfect end-to-end"
  Status: 🟢 Lossless (only shown if all conditions met)
  Conditions: source lossless + device lossless + no resampling


REAL-TIME UPDATES:
──────────────────

Signal path updates automatically in these scenarios:

1. TRACK CHANGE
   When: User skips to next track
   Updates: Source format (new track's file type)
   Example: FLAC → MP3 changes "Lossless" to "Converted"

2. ROUTE CHANGE
   When: Headphones plugged in, Bluetooth connected, etc
   Updates: Output device, bit-perfect flag
   Example: Wired → Bluetooth changes from "Lossless" to "Limited"

3. VOLUME CHANGE
   When: User adjusts volume slider
   Updates: Volume step, possibly overall status
   Example: 100% → 30% changes status from "Enhanced" to "Converted"

4. SESSION CHANGE
   When: AVAudioSession.sampleRate changes
   Updates: Sample rate, resampling status
   Example: 48 kHz → 44.1 kHz might affect bit-perfect status


QUALITY DETERMINATION LOGIC:
───────────────────────────

Overall Status = WORST step status (using severity scoring)
  Severity: Lossless (0) < Enhanced (1) < Converted (2) < Limited (3) < Unknown (4)

Bit-Perfect Calculation:
  isBitPerfect = (source is lossless)
              AND (device is lossless — not Bluetooth/AirPlay)
              AND (no resampling needed)

Example Scenarios:
  ✅ FLAC → Headphones (48 kHz) = Lossless (green badge)
  🟡 MP3 → Headphones = Converted (amber badge)
  🔴 FLAC → Bluetooth = Limited (red badge) [Bluetooth uses lossy codecs]
  ⚪ Track loading = Unknown (gray badge)

  Future: Use LMS API to get exact metadata

Limitation 2: Can't Detect Internal Resampling
  Workaround: Compare source format's typical rate with session rate
  Future: Inspect AVAudioEngine graph

Limitation 3: Can't Detect Device-Level DSP/EQ
  Workaround: Assume processing if wireless
  Future: Use OS metrics APIs or acoustic measurement

Limitation 4: Volume is App-Level, Not Sample-Level
  Workaround: Show available headroom at current volume
  Future: Real-time peak metering
